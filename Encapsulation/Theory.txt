## Encapsulation — Quick Revision Summary (OOP)

Encapsulation is one of the core ideas of Object-Oriented Programming, and the simplest way to remember it is:

> **Encapsulation = Wrapping data + controlling access to it**

But the real meaning goes deeper.

---

# 1. Core Idea (Must Remember)

Encapsulation means:

> **Bind data (variables) and functions (methods) together in a class, and restrict direct access to some of the data.**

So instead of:

```cpp
balance = -5000;   // dangerous
```

we force:

```cpp
deposit();
withdraw();
```

---

# 2. Real-Life Analogy (Very Important)

### 💊 Medicine Capsule

* You don’t see or change the medicine inside
* You only take it as a whole

👉 Internal details hidden, usage controlled

---

### 🏧 ATM Machine

You can:

* Withdraw money
* Deposit money
* Check balance

You cannot:

* Modify bank database
* Change internal logic

👉 You use a controlled interface

---

# 3. Why Encapsulation is Needed

Without encapsulation:

* Data can be changed freely
* No validation
* Leads to bugs and security issues

Example:

```cpp
class BankAccount {
public:
    int balance;
};
```

Problem:

```cpp
acc.balance = -100000; // invalid but allowed ❌
```

---

# 4. With Encapsulation (Safe Design)

```cpp
class BankAccount {
private:
    int balance;

public:
    void deposit(int amt) {
        if (amt > 0)
            balance += amt;
    }

    int getBalance() {
        return balance;
    }
};
```

Now:

```cpp
acc.balance = -1000; // ❌ not allowed
```

Only controlled access is allowed.

---

# 5. Access Specifiers

| Type        | Meaning                      |
| ----------- | ---------------------------- |
| `public`    | accessible everywhere        |
| `private`   | accessible only inside class |
| `protected` | used in inheritance          |

---

# 6. Getter & Setter (Most Common Pattern)

### Getter → read data

```cpp
int getAge() {
    return age;
}
```

### Setter → modify data safely

```cpp
void setAge(int a) {
    if (a > 0)
        age = a;
}
```

👉 This adds **validation + control**

---

# 7. Key Benefits

Encapsulation gives:

### ✔ Data protection

Prevents direct misuse

### ✔ Data validation

Only correct values allowed

### ✔ Flexibility

Internal code can change without affecting users

### ✔ Maintainability

Easier debugging and updates

### ✔ Security

Prevents unwanted access

---

# 8. Real-Life Analogy (Final Mental Model)

Think of a **smartphone app**:

You can:

* Click buttons
* Use features

You cannot:

* Modify source code
* Access internal database

👉 You interact through a controlled interface only

---

# 9. One-Line Exam Definition

> **Encapsulation is the process of bundling data and methods in a class and restricting direct access to data using access specifiers, allowing controlled access through public methods.**

---

# 10. Final Shortcut to Remember

Think:

> **“Hide data + Control access = Encapsulation”**

Or even simpler:

> **Capsule = Protected inside, controlled outside**
